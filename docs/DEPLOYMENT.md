# Deploying to Render

Three services: a static frontend, a Node backend, and PostgreSQL. The
`render.yaml` blueprint creates all three in one step.

---

## Fastest path: the blueprint

1. Push this repository to GitHub.
2. Render dashboard → **New** → **Blueprint**.
3. Select the repository. Render reads `render.yaml` and shows what it will
   create: `smarttv-frontend`, `smarttv-backend`, `smarttv-db`.
4. **Apply**.

That is the whole deployment. `SESSION_SECRET` and `LSL_SHARED_SECRET` are
generated by Render on first deploy, so they never pass through a keyboard or a
file. `DATABASE_URL` is wired automatically, and each service learns the other's
hostname without you typing either.

### Then, once

Copy `LSL_SHARED_SECRET` out of the backend's **Environment** tab into the
`TV Config` notecard in world. It is the only value you ever move by hand, and
only for the first pairing — after that each TV holds its own device secret.

### If the blueprint is rejected

**`services[1].plan — no such plan free for service type web`**
Static sites have no plan tier. Remove the `plan:` line from the
`smarttv-frontend` service entirely — only the database and the backend take
one. (Fixed in this repository; you would only see this on an older copy.)

**The database is rejected**
Render allows one free PostgreSQL per workspace. Either delete the existing
free database, or change `smarttv-db`'s plan to `basic-256mb`.

**`services[0]` errors instead**
That is the backend, a normal Node web service, where `plan: free` is valid.
An error there usually means a typo in the plan name rather than the tier.

## Manual setup

If you would rather not use the blueprint.

### Database

The blueprint does **not** create one. Render allows a single free PostgreSQL
per workspace, so this project is set up to share whatever database you already
have, kept apart inside its own schema.

Copy the **Internal Database URL** from any existing Postgres and paste it into
the backend's `DATABASE_URL` in the dashboard. Then set `DB_SCHEMA` (default
`smarttv`).

Every table, index and function this project creates goes inside that schema.
Nothing else in the database is read or modified, and names as generic as
`users`, `settings`, `favorites` and `history` cannot collide with another
application's tables of the same name.

Connections are pinned to the schema in the startup packet, with **no `public`
fallback on purpose**: if the schema is missing, queries fail loudly rather
than quietly creating our tables next to somebody else's.

If you would rather have a dedicated database, add a `databases:` block back to
`render.yaml` with `plan: basic-256mb`, or create one in the dashboard and point
`DATABASE_URL` at it — no code changes either way.

Migrations run automatically at boot. To run them yourself:

```bash
cd backend && DATABASE_URL="postgres://..." npm run migrate
```

The runner is idempotent — it tracks applied files in `schema_migrations` and
is safe on every deploy.

### Backend

**New → Web Service**, pointed at this repository.

| Setting | Value |
|---|---|
| Root directory | `backend` |
| Runtime | Node |
| Build command | `npm ci` |
| Start command | `npm start` |
| Health check path | `/api/health` |

Environment variables:

| Key | Value |
|---|---|
| `NODE_VERSION` | `20` |
| `NODE_ENV` | `production` |
| `DATABASE_URL` | from the database above |
| `SESSION_SECRET` | `openssl rand -hex 32` |
| `LSL_SHARED_SECRET` | `openssl rand -hex 24` |
| `FRONTEND_URL` | the frontend's URL, once it exists |
| `LOG_LEVEL` | `info` |

`backend/.env.example` documents every variable, including the optional ones.

### Frontend

**New → Static Site**, same repository.

| Setting | Value |
|---|---|
| Root directory | `frontend` |
| Build command | `node build-config.js` |
| Publish directory | `.` |

Environment variables:

| Key | Value |
|---|---|
| `BACKEND_URL` | the backend's URL |
| `LOGO_URL` | optional, overrides the bundled logo |
| `BRAND_NAME` | optional, overrides the name |

The build step writes `config.generated.js` from those variables. It contains
public URLs only — there are no secrets in the frontend, ever.

## WebSockets

Nothing to configure. Render web services carry WebSocket upgrades on the same
port as HTTP, which is why `server.js` attaches the WebSocket server to the
Express HTTP server rather than opening a second listener. The frontend derives
`wss://` from the backend URL automatically.

## CORS

The allow list is built in `backend/src/middleware/security.js` from
`FRONTEND_URL` plus anything in `EXTRA_CORS_ORIGINS`, and localhost is added
only when `NODE_ENV` is not production. There is no wildcard: a wildcard would
let any page on the internet drive somebody's TV.

Requests from Second Life carry no `Origin` header at all — they are
server-to-server and authenticated by signature instead, in `lslAuth.js`.

## Verifying the deployment

```bash
curl https://your-backend.onrender.com/api/health
```

The response names each subsystem. It reports `database: unavailable` honestly
rather than returning a green light that lies — and still returns 200, because
the service genuinely does still work without one.

Then open the frontend URL in an ordinary browser. You should get the boot
screen, then the home screen, with the cloud indicator turning green. That is
the whole TV interface, before Second Life is involved at all, which makes it
the quickest place to check a deployment.

## Free tier, honestly

Free web services sleep after about 15 minutes idle. The next request takes
roughly 50 seconds to wake them and WebSockets drop when they sleep. The TV
handles this — it degrades to local mode, shows "Local only", and reconnects by
itself — but people will notice. Free PostgreSQL instances also expire.

For a TV people actually use, put the backend and database on paid tiers. The
frontend is a static site and is fine on free.

## Updating

Both services have `autoDeploy: true`, so pushing to the default branch
redeploys them. Migrations run at boot. The in-world scripts are **not** updated
by a deploy — LSL lives in the object, so re-paste any script you changed.
